## Стрингове и изход

### `echo` — отпечатване на текст

`echo` отпечатва текст в терминала. Прост на пръв поглед, но с важни детайли.

```bash
echo "Здравей, свят!"          # Здравей, свят!
echo Здравей                   # работи и без кавички
echo                           # отпечатва празен ред
echo -n "Без нов ред"          # -n: не добавя \n в края
echo -e "Ред 1\nРед 2"         # -e: интерпретира escape символи
echo -e "Колона1\tКолона2"     # \t = табулация
```

| Флаг | Значение                                           |
| ---- | -------------------------------------------------- |
| `-n` | не добавя нов ред в края                           |
| `-e` | интерпретира `\n`, `\t`, `\\` и др. escape символи |
| `-E` | изключва интерпретацията (по подразбиране)         |

```bash
# Escape символи с -e:
echo -e "\n--- Заглавие ---\n"   # празен ред преди и след
echo -e "Червено: \e[31mТекст\e[0m"  # ANSI цветове в терминала
```

> **`echo` vs `printf`:** За по-сложно форматиране е по-надеждно да се използва `printf` — поведението на `echo` с флагове се различава между различните shell-ове. `echo` е удобен за бързо отпечатване, `printf` за скриптове.

### Двойни кавички `""`

Двойните кавички **запазват буквалния смисъл на повечето символи**, но позволяват **заместване на променливи и команди**. Bash чете вътрешността и заменя `$VAR`, `$()` и `\` с реалните им стойности.

```bash
name="Ivan"
echo "Здравей, $name!"         # Здравей, Ivan!
echo "Домашната ти директория е $HOME"   # /home/ivan
echo "Сега е $(date)"          # Сега е Tue Mar 17 10:22:00 2026
echo "Цена: \$5"               # Цена: $5  (\ escape-ва $)
```

### Единични кавички `''`

Единичните кавички са **буквални** — всичко вътре се третира като чист текст. Никакво заместване, никакви специални символи. Дори `\` няма специален смисъл.

```bash
echo 'Здравей, $name!'         # Здравей, $name!  (не замества)
echo 'Домашната ти директория е $HOME'   # $HOME (буквално)
echo 'Сега е $(date)'          # Сега е $(date)  (не изпълнява)
echo 'Backslash: \'            # грешка — не можеш да escape-неш ' с '
```

### Правилото

| Ситуация                                 | Кавички      |
| ---------------------------------------- | ------------ |
| Искаш да замести променливи              | `"двойни"`   |
| Искаш буквален текст, без заместване     | `'единични'` |
| Стрингът съдържа единични кавички        | `"двойни"`   |
| Стрингът съдържа специални shell символи | `'единични'` |

```bash
echo "It's a test"             # работи — единична кавичка вътре в двойни
echo 'Say "hello"'             # работи — двойни вътре в единични
echo "Цена: \$5.00"            # escape с \ вътре в двойни
```

### Операции с низове

```bash
str="Hello, World"

echo ${#str}                   # 12 — дължина на стринга
echo ${str:7}                  # World — от позиция 7 нататък
echo ${str:7:5}                # World — от позиция 7, 5 символа
echo ${str/World/Bash}         # Hello, Bash — замества първото съвпадение
echo ${str//l/L}               # HeLLo, WorLd — замества всички съвпадения
echo ${str,,}                  # hello, world — всичко малки букви
echo ${str^^}                  # HELLO, WORLD — всичко главни букви

path="/home/ivan/notes.txt"
echo ${path##*/}               # notes.txt — само името на файла (след последния /)
echo ${path%/*}                # /home/ivan  — директорията (преди последния /)
echo ${path##*.}               # txt — само разширението
```

### Стойности по подразбиране

```bash
# Ако $name не е зададено или е празно — използвай стойност по подразбиране
echo ${name:-"Гост"}           # показва "Гост" ако $name е празно
echo ${name:="Гост"}           # задава $name="Гост" ако е празно
echo ${name:?"Грешка: name не е зададено"}  # показва грешка ако е празно
```

## `printf` — форматиран изход

`printf` е командата за **прецизно, преносимо форматиране на изход**. За разлика от `echo`, тя не добавя автоматично нов ред и изисква изричен шаблон (format string), в който се описва точно как да изглежда всяка стойност.

### Основен синтаксис

```bash
printf "ШАБЛОН" аргумент1 аргумент2 ...
```

Шаблонът съдържа обикновен текст и **спецификатори на формат**, започващи с `%`. Всеки спецификатор „поглъща“ следващия аргумент и го форматира по указания начин.

```bash
printf "Здравей, %s!\n" "Иван"        # Здравей, Иван!
printf "%s е на %d години\n" "Иван" 25   # Иван е на 25 години
printf "Резултат: %d\n" 42            # Резултат: 42
```

> **Важно:** `printf` **не** добавя нов ред автоматично — за разлика от `echo`. Ако искаш нов ред, трябва изрично да напишеш `\n` в шаблона.

### Спецификатори на формат (conversion specifiers)

Всеки спецификатор има формата: `%[флагове][ширина][.точност]буква`

| Спецификатор | Значение                                              |
| ------------- | ------------------------------------------------------ |
| `%s`          | стринг                                                  |
| `%d`, `%i`    | цяло число (десетично, знаково)                        |
| `%u`          | цяло число без знак (unsigned)                          |
| `%f`          | число с плаваща запетая (по подразбиране 6 знака след `.`) |
| `%e`, `%E`    | число в експоненциален (научен) запис                  |
| `%g`, `%G`    | по-краткият от `%f` или `%e` — избира автоматично       |
| `%o`          | число в осмична (octal) бройна система                  |
| `%x`          | число в шестнайсетична бройна система, малки букви      |
| `%X`          | число в шестнайсетична бройна система, главни букви      |
| `%c`          | единичен символ                                          |
| `%b`          | стринг, при който се интерпретират escape последователности (`\n`, `\t`) |
| `%q`          | стринг, екраниран (quoted) така, че да е валиден за повторно въвеждане в shell |
| `%%`          | буквален знак `%` (не поглъща аргумент)                 |

```bash
printf "%s\n" "текст"          # текст
printf "%d\n" 255              # 255
printf "%f\n" 3.14159          # 3.141590
printf "%e\n" 123456           # 1.234560e+05
printf "%o\n" 8                # 10   (осмично)
printf "%x\n" 255              # ff   (шестнайсетично)
printf "%X\n" 255              # FF
printf "%c\n" "A"              # A
printf "100%%\n"               # 100%
printf "%b\n" "Ред1\nРед2"     # Ред1 и Ред2 на отделни редове
```

### Ширина на полето (field width)

Число преди буквата на спецификатора задава **минималната ширина** на полето. По подразбиране подравняването е **дясно**.

```bash
printf "%10s\n" "hi"           # "        hi"   (дясно подравнено, 10 символа общо)
printf "%10d\n" 42             #  "        42"
printf "%5d\n" 42              #     "   42"
```

### Ляво подравняване — флагът `-`

Знакът `-` преди ширината подравнява съдържанието **ляво**, като допълва с интервали отдясно.

```bash
printf "%-10s|\n" "hi"         # "hi        |"
printf "%-10s%5d\n" "Иван" 25  # "Иван          25"
```

Това е особено полезно за таблично форматиран изход:

```bash
printf "%-15s %5s\n" "Име" "Възраст"
printf "%-15s %5d\n" "Иван" 25
printf "%-15s %5d\n" "Мария" 30
# Резултат:
# Име              Възраст
# Иван                  25
# Мария                 30
```

### Запълване с нули — флагът `0`

Знакът `0` (вместо интервали) допълва числата отляво с нули до зададената ширина. Работи само за числови спецификатори.

```bash
printf "%05d\n" 42             # 00042
printf "%08.2f\n" 3.14         # 00003.14
```

### Точност (precision) — `.N`

Точността, изписана след `.`, има различен смисъл според типа:

| Тип           | Значение на `.N`                                      |
| ------------- | -------------------------------------------------------- |
| `%f`, `%e`    | брой цифри след десетичната запетая                       |
| `%s`          | максимален брой символи, взети от стринга (отрязва останалото) |
| `%d`, `%i`    | минимален брой цифри (допълва с водещи нули)               |

```bash
printf "%.2f\n" 3.14159        # 3.14
printf "%.0f\n" 3.7            # 4   (закръгля)
printf "%10.2f\n" 3.14159      # "      3.14"  (ширина 10, 2 знака след запетая)
printf "%.3s\n" "hello"        # hel   (само първите 3 символа)
printf "%.5d\n" 42             # 00042
```

### Знак за положителни числа — флагът `+`

```bash
printf "%+d\n" 42              # +42
printf "%+d\n" -42             # -42  (отрицателните винаги показват знак)
```

### Интервал пред положително число — флагът (space)

```bash
printf "% d\n" 42              #  42   (интервал вместо знак пред положителни)
printf "% d\n" -42             # -42
```

### Алтернативна форма — флагът `#`

Добавя представка/суфикс, характерен за бройната система, при `%o`, `%x`, `%X`.

```bash
printf "%#o\n" 8                # 010   (с водещо 0)
printf "%#x\n" 255              # 0xff  (с представка 0x)
printf "%#X\n" 255              # 0XFF
```

### Динамична ширина/точност с `*`

Вместо да пишеш ширината директно в шаблона, можеш да я подадеш като аргумент, използвайки `*`.

```bash
printf "%*d\n" 10 42           # ширината (10) идва като първи аргумент → "        42"
printf "%.*f\n" 2 3.14159      # точността (2) идва като аргумент → 3.14
```

### Многократно прилагане на шаблона

Ако подадеш **повече аргументи**, отколкото спецификатори в шаблона, `printf` **повтаря шаблона** отново и отново, докато не изчерпи всички аргументи. Това е изключително полезно за печатане на списъци и таблици.

```bash
printf "%s\n" "a" "b" "c"
# a
# b
# c

printf "%-10s%5d\n" "Иван" 25 "Мария" 30 "Петър" 35
# Иван            25
# Мария           30
# Петър           35

# Всяко от трите двойки (име, число) използва отново същия шаблон
```

Ако аргументите свършат преди шаблонът да приключи, липсващите числови спецификатори се третират като `0`, а стринговите — като празен низ.

```bash
printf "%s-%s\n" "само-един"
# само-един-
```

### Escape последователности в шаблона

`printf` винаги интерпретира стандартните escape последователности в шаблона (не се нуждае от `-e` както `echo`):

| Escape | Значение          |
| ------ | ------------------ |
| `\n`   | нов ред             |
| `\t`   | табулация           |
| `\\`   | обратна наклонена черта |
| `\"`   | двойна кавичка      |
| `\a`   | звуков сигнал (alert) |
| `\r`   | carriage return     |
| `\0NNN`| символ по осмичен код |
| `\xHH` | символ по шестнайсетичен код |

```bash
printf "Ред1\nРед2\n"
printf "Колона1\tКолона2\n"
printf "Цитат: \"текст\"\n"
```

### Запис в променлива — флагът `-v`

`printf -v` записва форматирания резултат директно в **променлива**, вместо да го отпечатва на екрана.

```bash
printf -v greeting "Здравей, %s!" "Иван"
echo "$greeting"                # Здравей, Иван!

printf -v padded "%05d" 42
echo "$padded"                  # 00042
```

Това е по-бързо и по-чисто от `var=$(printf ...)`, защото не създава подпроцес.

### Комбиниране на флагове

Флаговете и ширината/точността могат да се комбинират свободно в един спецификатор:

```bash
printf "%-+10.2f|\n" 3.14159    # "+3.14     |"
#        ││ │ └─ точност: 2 знака след запетая
#        ││ └─── ширина: 10
#        │└───── + : винаги показва знак
#        └────── - : ляво подравняване
```

### Практически примери

```bash
# Таблица с подравнени колони
printf "%-10s %-10s %8s\n" "Име" "Отдел" "Заплата"
printf "%-10s %-10s %8.2f\n" "Иван" "IT" 2500.5
printf "%-10s %-10s %8.2f\n" "Мария" "HR" 2100

# Генериране на прогрес бар / повтарящи се символи
printf '%.0s#' {1..20}; echo    # 20 пъти символа #

# Формат на дата
printf "Дата: %02d/%02d/%04d\n" 5 9 2026   # Дата: 05/09/2026

# Числа с водещи нули (напр. номериране на файлове)
for i in {1..5}; do
  printf "file_%03d.txt\n" "$i"
done
# file_001.txt
# file_002.txt
# ...

# Конвертиране между бройни системи
printf "%d -> hex: %x, oct: %o\n" 255 255 255   # 255 -> hex: ff, oct: 377

# Съобщение за грешка към stderr с форматиране
printf "Грешка: %s (код %d)\n" "файлът не е намерен" 2 >&2

# Безопасно екраниране на аргументи за shell (%q)
printf "%q\n" "файл с интервали.txt"   # файл\ с\ интервали.txt
```

> **`printf` vs `echo` — обобщение:** Използвай `printf`, когато имаш нужда от точен контрол върху формата (подравняване, брой знаци след десетичната запетая, водещи нули, повторение на шаблон за списъци) или когато преносимостта между shell-ове е важна. Използвай `echo`, когато просто искаш бързо да покажеш текст.

## `date` — работа с дата и час

`date` показва (или задава) текущата дата и час на системата. Изключително често се среща в комбинация с `$()`, за timestamp-и в имена на файлове, логове и backup-и.

### Основен синтаксис

```bash
date                            # показва текущата дата и час в пълен формат
# Tue Mar 17 10:22:00 EET 2026
```

### Форматиране с `+`

Флагът `+` последван от **формат стринг** контролира точно какво и как да се покаже. Форматът съдържа `%`-спецификатори, подобно на `printf`.

```bash
date +"%Y-%m-%d"                # 2026-03-17
date +"%H:%M:%S"                # 10:22:00
date +"%Y-%m-%d %H:%M:%S"       # 2026-03-17 10:22:00
date +"%A, %d %B %Y"            # Tuesday, 17 March 2026
```

| Спецификатор | Значение |
|---------------|----------|
| `%Y` | година, 4 цифри (2026) |
| `%y` | година, 2 цифри (26) |
| `%m` | месец, 2 цифри (01-12) |
| `%d` | ден от месеца, 2 цифри (01-31) |
| `%H` | час, 24-часов формат (00-23) |
| `%I` | час, 12-часов формат (01-12) |
| `%M` | минути (00-59) |
| `%S` | секунди (00-59) |
| `%A` | пълно име на деня (Tuesday) |
| `%a` | съкратено име на деня (Tue) |
| `%B` | пълно име на месеца (March) |
| `%b` | съкратено име на месеца (Mar) |
| `%j` | ден от годината (001-366) |
| `%s` | Unix timestamp (секунди от 1 януари 1970) |
| `%Z` | часова зона (EET) |
| `%%` | буквален знак `%` |

### `date` в command substitution

Най-честата употреба на `date` е вътре в `$()` — за timestamp в имена на файлове или логове:

```bash
today=$(date +%Y-%m-%d)
echo "Днес е $today"                        # Днес е 2026-03-17

mkdir "backup_$(date +%Y%m%d_%H%M%S)"       # backup_20260317_102200
cp report.txt "report_$(date +%Y-%m-%d).txt"

echo "[$(date +'%Y-%m-%d %H:%M:%S')] Скриптът стартира" >> app.log
```

### Unix timestamp — `%s`

`%s` връща броя секунди от 1 януари 1970 (Unix epoch) — удобно за изчисляване на разлики във времето или уникални идентификатори.

```bash
date +%s                        # 1773744120

# Измерване на времетраене на команда
start=$(date +%s)
sleep 3
end=$(date +%s)
echo "Отне $((end - start)) секунди"        # Отне 3 секунди
```

### `-d` — показване на друга дата (не текущата)

Флагът `-d` (GNU `date`) позволява изчисляване спрямо произволна дата, включително относителни изрази.

```bash
date -d "yesterday"                          # вчера, същия час
date -d "2026-01-01"                         # конкретна дата
date -d "next monday"                        # следващия понеделник
date -d "3 days ago"                         # преди 3 дни
date -d "+1 week"                            # след една седмица
date -d "2026-03-17" +%A                     # какъв ден е бил/ще бъде
```

### Практически примери

```bash
# Backup с timestamp в името
tar -czf "backup_$(date +%Y%m%d_%H%M%S).tar.gz" ./project

# Логване с точен час на всеки ред
while true; do
  echo "[$(date +'%H:%M:%S')] Проверка на статуса..."
  sleep 60
done

# Изчисляване на възраст на файл в дни
file_time=$(date -r file.txt +%s)
now=$(date +%s)
echo "Файлът е стар $(( (now - file_time) / 86400 )) дни"

# Форматиран изход, комбиниран с printf
printf "Генерирано на: %s\n" "$(date +'%d.%m.%Y %H:%M')"
```

> **Забележка:** Синтаксисът на `-d` и наличните формати може леко да се различават между GNU `date` (Linux) и BSD `date` (macOS). Примерите по-горе са за GNU `date`.

## Заместване

### `$()` — Command Substitution

`$()` изпълнява команда и **замества израза с нейния изход**. Можеш да използваш резултата от всяка команда навсякъде — в присвоявания, в стрингове, като аргументи.

```bash
echo "Днес е $(date +%A)"              # Днес е Tuesday
echo "Потребителят е $(whoami)"        # Потребителят е ivan
echo "Файлове: $(ls | wc -l)"          # Файлове: 42

# Присвояване
today=$(date +%Y-%m-%d)
files=$(find . -name "*.log" | wc -l)
current_dir=$(pwd)

# Като аргумент на друга команда
mkdir "backup_$(date +%Y%m%d)"        # backup_20260317
cat $(find . -name "*.conf")          # прочита всички .conf файлове
```

Вложено заместване — `$()` може да се влага:

```bash
echo "Последен файл: $(ls -t $(pwd) | head -1)"
```

> **`$()` vs `` ` `` `` ` ``:** Старият синтаксис за command substitution са обратни кавички `` `команда` ``. Двете са еквивалентни, но `$()` е препоръчван — по-лесен за четене и влагане.

### `$(())` — Arithmetic Substitution

`$(())` изчислява **аритметични изрази** с цели числа и замества резултата.

```bash
echo $((3 + 5))                # 8
echo $((10 * 4 - 2))           # 38
echo $((10 / 3))               # 3  (целочислено деление!)
echo $((10 % 3))               # 1  (остатък)
echo $((2 ** 8))               # 256 (степенуване)

a=10
b=3
echo $((a + b))                # 13
echo $((a * b))                # 30

# Инкремент
count=0
count=$((count + 1))
echo $count                    # 1

# В стрингове
echo "5 на квадрат е $((5**2))"     # 5 на квадрат е 25
echo "RAM: $(($(free -m | awk 'NR==2{print $2}') )) MB"
```

> **Важно:** `$(())` работи само с **цели числа**. За десетични числа се използва `bc` или `awk`:

```bash
echo "scale=2; 10 / 3" | bc        # 3.33
awk 'BEGIN { print 10 / 3 }'       # 3.33333
```

## `bc` — калкулатор с плаваща запетая

`bc` (**B**asic **C**alculator) е самостоятелен калкулатор командата, който за разлика от `$(())` поддържа **дробни числа** и произволна точност. Чете изрази от `stdin` (обикновено подадени през pipe) и връща резултата.

### Основен синтаксис

```bash
echo "5 + 3" | bc                  # 8
echo "10 / 3" | bc                 # 3   (по подразбиране цялостно деление, БЕЗ scale!)
echo "2 ^ 10" | bc                 # 1024  (степенуване, различно от $(( )) синтаксиса)
```

> **Внимание:** Без изрично зададен `scale`, `bc` върши **целочислено деление**, точно както `$(())` — резултатът от `10 / 3` е `3`, не `3.33`. `scale` е задължителен за дробен резултат.

### `scale` — брой цифри след десетичната запетая

`scale` е специална вградена променлива на `bc`, която определя **точността** на резултата.

```bash
echo "scale=2; 10 / 3" | bc        # 3.33
echo "scale=4; 10 / 3" | bc        # 3.3333
echo "scale=0; 10 / 3" | bc        # 3   (без дробна част)
echo "scale=10; 22 / 7" | bc       # 3.1428571428  (приближение на π)
```

Няколко израза могат да се разделят с `;`:

```bash
echo "scale=2; a=10; b=3; a/b" | bc      # 3.33
```

### Основни операции

```bash
echo "5 + 3" | bc                  # 8
echo "5 - 3" | bc                  # 2
echo "5 * 3" | bc                  # 15
echo "scale=2; 5 / 3" | bc         # 1.66
echo "5 % 3" | bc                  # 2   (остатък от делене)
echo "2 ^ 10" | bc                 # 1024  (степенуване)
echo "scale=4; sqrt(2)" | bc       # 1.4142  (квадратен корен — вградена функция)
```

### `-l` — математическа библиотека

Флагът `-l` зарежда стандартната математическа библиотека на `bc`, добавяйки функции като `s()` (синус), `c()` (косинус), `l()` (натурален логаритъм), `e()` (експонента), и автоматично задава `scale=20`.

```bash
echo "scale=4; s(1)" | bc -l       # 0.8414  (sin(1) в радиани)
echo "scale=4; 4*a(1)" | bc -l     # 3.1415  (a() = arctan, 4*atan(1) = π)
```

### Използване в скриптове чрез command substitution

Тъй като `bc` чете от `stdin`, най-честият начин да вкараш резултата в bash променлива е чрез `$()`:

```bash
result=$(echo "scale=2; 10 / 3" | bc)
echo "Резултатът е: $result"       # Резултатът е: 3.33

# С heredoc за по-дълги изрази
result=$(bc <<< "scale=2; (15 + 7) / 2")
echo $result                        # 11.00

# Подаване на променливи от bash към bc
a=15
b=4
echo "scale=3; $a / $b" | bc        # 3.750
```

### `bc` срещу `$(())` и `awk`

| Инструмент | Цели числа | Дробни числа | Точност | Удобство в скрипт |
|------------|:----------:|:-------------:|---------|---------------------|
| `$(())` | ✅ | ❌ | — | най-бърз, вграден в bash, без нужда от pipe |
| `bc` | ✅ | ✅ (със `scale`) | произволна, зададена от потребителя | изисква pipe/heredoc, най-прецизен |
| `awk` | ✅ | ✅ | плаваща запетая (double) | удобен, ако вече обработваш данни с `awk` |

```bash
# Едно и също изчисление с трите инструмента:
echo $((10 / 3))                        # 3        — $(()) — само цяло число
echo "scale=4; 10 / 3" | bc              # 3.3333   — bc — точна, зададена точност
awk 'BEGIN { print 10 / 3 }'             # 3.33333  — awk — double precision
```

### Практически примери

```bash
# Изчисляване на процент
echo "scale=2; 45 / 200 * 100" | bc      # 22.50

# Конвертиране на единици (км в мили)
km=10
echo "scale=2; $km * 0.621371" | bc      # 6.21

# Сума на числа от файл (едно число на ред)
paste -sd+ numbers.txt | bc

# Средна стойност
total=$(paste -sd+ numbers.txt | bc)
count=$(wc -l < numbers.txt)
echo "scale=2; $total / $count" | bc
```

## Помощни команди

### `sort` — сортиране

`sort` сортира редовете на текстов вход. По подразбиране — лексикографски (азбучен ред).

```bash
sort file.txt                  # сортира азбучно
sort -r file.txt               # обратен ред
sort -n numbers.txt            # числово сортиране (не лексикографско)
sort -u file.txt               # премахва дубликатите (unique)
sort -k2 file.txt              # сортира по второто поле
sort -k2 -n file.txt           # сортира числово по второто поле
sort -t: -k3 -n /etc/passwd    # сортира по 3-то поле, разделено с ':'
```

| Флаг       | Значение                            |
| ---------- | ----------------------------------- |
| `-r`       | обратен ред                         |
| `-n`       | числово сортиране                   |
| `-u`       | само уникални редове                |
| `-k <N>`   | сортира по N-то поле                |
| `-t <sep>` | задава разделителя на полетата      |
| `-f`       | игнорира главни/малки букви         |
| `-h`       | сортира четими размери (1K, 2M, 3G) |
| `-R`       | случаен ред (разбъркване)           |

```bash
# Практически примери
du -sh * | sort -h             # сортира файлове по размер (четимо)
cat access.log | sort -k9 -n  # сортира лог по статус код
sort -t, -k2 data.csv          # сортира CSV по втора колона
```

> **Важно:** `sort -u` и `uniq` не са едно и също. `sort -u` едновременно сортира и премахва дубликатите в целия поток. `uniq` работи само върху **съседни** еднакви редове — затова обикновено се комбинира със `sort`.

---

### `uniq` — работа с дублиращи се съседни редове

`uniq` премахва или брои **повтарящи се съседни редове**. Ключовата дума тук е **съседни** — ако еднаквите редове не са един до друг, `uniq` няма да ги счита за дубликати.

```bash
printf "a\na\nb\nb\nb\nc\n" | uniq
# a
# b
# c

printf "a\nb\na\n" | uniq
# a
# b
# a
# "a" не се премахва, защото не е съседен на предишното "a"
```

#### Как работи

`uniq` сравнява текущия ред с **предишния**. Ако са еднакви, по подразбиране отпечатва само първия от групата.

```
Вход                    Изход на uniq
──────────────────      ─────────────
apple                   apple
apple                   banana
banana                  carrot
banana
carrot
```

Затова в реални pipeline-и почти винаги ще видиш:

```bash
sort file.txt | uniq
sort file.txt | uniq -c
sort file.txt | uniq -d
```

#### Полезни флагове

| Флаг     | Значение                                        |
| -------- | ----------------------------------------------- |
| `-c`     | показва колко пъти се среща всеки ред           |
| `-d`     | показва само редовете, които имат дубликати     |
| `-u`     | показва само уникалните редове (без повторения) |
| `-i`     | case-insensitive сравнение                      |
| `-f <N>` | игнорира първите N полета при сравнение         |
| `-s <N>` | игнорира първите N символа при сравнение        |
| `-w <N>` | сравнява само първите N символа                 |

```bash
sort names.txt | uniq -c          # брои срещанията
sort names.txt | uniq -d          # само стойностите с дубликати
sort names.txt | uniq -u          # само стойностите, които се срещат веднъж
sort names.txt | uniq -i          # игнорира главни/малки букви
```

#### Разлика между `-d`, `-u` и `-c`

```bash
printf "a\na\nb\nc\nc\n" | uniq -c
# 2 a
# 1 b
# 2 c

printf "a\na\nb\nc\nc\n" | uniq -d
# a
# c

printf "a\na\nb\nc\nc\n" | uniq -u
# b
```

- `-c` показва **всички** групи + колко пъти се срещат.
- `-d` показва само групите с **повече от едно** срещане.
- `-u` показва само групите с **точно едно** срещане.

#### Игнориране на части от реда

```bash
# Игнорира първото поле и сравнява по остатъка
printf "1 apple\n2 apple\n3 banana\n" | uniq -f 1
# 1 apple
# 3 banana

# Игнорира първите 3 символа
printf "ID1_test\nID2_test\nID3_prod\n" | uniq -s 3
# ID1_test
# ID3_prod
```

> **Важно:** `-f` работи по **полета** (разделени по whitespace), а `-s` по **символи**.

#### Практически примери

```bash
# Най-често срещани IP адреси
awk '{print $1}' access.log | sort | uniq -c | sort -rn

# Намери дублиращи се имена в списък
sort students.txt | uniq -d

# Премахни duplicate редове от файл
sort file.txt | uniq > unique.txt
```

### `tr` — трансформация на символи

`tr` (**tr**anslate) заменя или изтрива отделни символи. Работи само с **отделни символи**, не с низове.

```bash
echo "hello" | tr 'a-z' 'A-Z'         # HELLO — малки в главни
echo "HELLO" | tr 'A-Z' 'a-z'         # hello — главни в малки
echo "hello world" | tr ' ' '_'       # hello_world — интервали в _
echo "hello" | tr -d 'l'              # heo — изтрива всички 'l'
echo "aabbcc" | tr -s 'a-z'           # abc — squeeze (премахва повтарящи се)
echo "abc123" | tr -d '0-9'           # abc — изтрива цифрите
```

| Флаг | Значение                                              |
| ---- | ----------------------------------------------------- |
| `-d` | delete — изтрива символите                            |
| `-s` | squeeze — свива повторенията в едно                   |
| `-c` | complement — работи с всичко ОСВЕН посочените символи |

```bash
# Полезни класове символи
echo "Hello 123!" | tr -d '[:digit:]'      # Hello !  (изтрива цифри)
echo "Hello 123!" | tr -d '[:alpha:]'      #  123!    (изтрива букви)
echo "Hello 123!" | tr -d '[:space:]'      # Hello123! (изтрива интервали)
echo "Hello\tWorld" | tr '\t' ' '          # замества tab с интервал
```

### `cut` — изрязване на колони

`cut` извлича конкретни **полета (колони)** или **символи** от всеки ред.

```bash
# По разделител (-d) и поле (-f)
echo "ivan:1000:developers" | cut -d: -f1         # ivan
echo "ivan:1000:developers" | cut -d: -f2         # 1000
echo "ivan:1000:developers" | cut -d: -f1,3       # ivan:developers
echo "ivan:1000:developers" | cut -d: -f2-        # 1000:developers (от 2 до края)

# По позиция на символи (-c)
echo "Hello, World!" | cut -c1-5                  # Hello
echo "Hello, World!" | cut -c8-                   # World!
```

| Флаг       | Значение                                      |
| ---------- | --------------------------------------------- |
| `-d <sep>` | задава разделителя (по подразбиране: tab)     |
| `-f <N>`   | избира поле N (или диапазон: `1-3`, или `2-`) |
| `-c <N>`   | избира символи по позиция                     |

```bash
# Практически примери
cut -d: -f1 /etc/passwd              # само потребителските имена
cut -d, -f2,4 data.csv               # 2-ра и 4-та колона от CSV
ls -l | cut -c1-10                   # само правата от ls -l
```

> **`cut` vs `awk`:** `cut` е по-бърз и по-прост за еднократно извличане на колони. `awk` е по-мощен когато трябва обработка или логика върху данните.

## `pwgen` — генериране на пароли

`pwgen` генерира произволни, сравнително лесни за произнасяне пароли — удобна помощна команда, когато е нужна бърза, случайна стойност (парола, временен таен ключ, тестови данни).

> **Инсталация:** `pwgen` не винаги е инсталиран по подразбиране. `sudo apt install pwgen` (Debian/Ubuntu) или `sudo dnf install pwgen` (Fedora).

### Основен синтаксис

```bash
pwgen                          # генерира множество пароли с дължина 8, в колони
pwgen 12                       # пароли с дължина 12 символа
pwgen 12 1                     # само ЕДНА парола с дължина 12
```

По подразбиране `pwgen` отпечатва **много пароли наведнъж**, подредени в колони, за да можеш да избереш ръчно тази, която ти харесва визуално.

### Най-често използвани флагове

```bash
pwgen -s 16 1                  # -s: secure — напълно случайна (не "лесна за произнасяне")
pwgen -y 12 1                  # -y: включва символи (!@#$%^&*)
pwgen -c 12 1                  # -c: поне една главна буква (capitalize)
pwgen -n 12 1                  # -n: поне една цифра
pwgen -B 12 1                  # -B: без objected("объркващи") символи (0/O, 1/l/I)
pwgen -1 12 5                  # -1: една парола на ред (лесно за grep/четене в скрипт)
```

| Флаг | Значение |
|------|----------|
| `-s` | secure — максимално случайна, без "произносим" алгоритъм |
| `-y` | добавя специални символи |
| `-c` | гарантира поне една главна буква |
| `-n` | гарантира поне една цифра |
| `-B` | избягва двусмислени символи (0/O, 1/l/I) |
| `-1` | една парола на ред в изхода (по подразбиране са в колони) |
| `-N <брой>` | брой генерирани пароли |

### Комбиниране на флагове

```bash
pwgen -sy1 20 5                # 5 напълно случайни пароли, 20 символа, със спец. символи, по една на ред
pwgen -cn1 16 1                # 1 парола, 16 символа, с главна буква и цифра
```

### Използване в скриптове

Тъй като `pwgen` пише на `stdout`, най-лесно се комбинира с `$()`, за да се запази в променлива:

```bash
new_password=$(pwgen -s1 16 1)
echo "Новата парола е: $new_password"

# Генериране на пароли за списък с потребители
for user in ivan maria petar; do
  pass=$(pwgen -s1 14 1)
  echo "$user:$pass"
done
```

### Практически примери

```bash
# Генерира парола и я копира директно в променлива за нов потребител
useradd newuser
password=$(pwgen -s1 16 1)
echo "newuser:$password" | chpasswd
echo "Паролата за newuser е: $password"

# Генерира 5 кандидат-пароли за ръчен избор
pwgen -sy 16 5

# Създава файл с временни пароли за няколко акаунта
for i in {1..3}; do
  pwgen -s1 12 1
done > temp_passwords.txt
```

> **Бележка:** `pwgen` е удобен за бързо генериране на случайни стойности в скриптове и учебни примери. За production системи, изискващи криптографски сигурни пароли/токени, `openssl rand -base64 32` или `/dev/urandom` са по-стандартните инструменти.

## `xargs` — превръщане на изход в аргументи

`xargs` решава един фундаментален проблем в терминала: повечето команди не четат от стандартния вход (`stdin`) — те очакват аргументи. `xargs` взима редовете от `stdin` и ги **превръща в аргументи** на друга команда.

#### Защо е нужен

```bash
# Проблемът: find намери файловете, но rm не чете от stdin
find . -name "*.tmp" | rm          # ✗  не работи — rm не чете от pipe

# Решението с xargs:
find . -name "*.tmp" | xargs rm    # ✓  xargs взима пътищата и ги подава на rm
```

Без `xargs` единствената алтернатива е `-exec` при `find`, но `xargs` е по-гъвкав и работи с всяка команда.

#### Как работи

`xargs` чете `stdin` ред по ред, натрупва аргументите и извиква командата — по подразбиране с **всички аргументи наведнъж** в края:

```
find . -name "*.log"    →    изход:
                              ./app.log
                              ./error.log
                              ./access.log
                                   │
                                   ▼ xargs rm
                         rm ./app.log ./error.log ./access.log
                         └── една команда с три аргумента
```

Сравни с `-exec ... \;` при `find`, което извиква командата поотделно за всеки файл — `xargs` е значително по-бързо при много файлове.

#### Основна употреба

```bash
find . -name "*.tmp" | xargs rm                  # изтрива всички .tmp файлове
find . -name "*.jpg" | xargs ls -lh              # показва детайли за снимките
find . -type f -name "*.py" | xargs wc -l        # брои редовете в .py файловете
echo "file1.txt file2.txt" | xargs cat           # показва съдържанието на двата файла
```

#### Флагове

| Флаг                | Значение                                                              |
| ------------------- | --------------------------------------------------------------------- |
| `-I {}`             | задава placeholder — `{}` се замества с всеки аргумент поотделно      |
| `-n <N>`            | подава максимум N аргумента на извикване                              |
| `-P <N>`            | паралелно изпълнение с N процеса едновременно                         |
| `-0`                | аргументите са разделени с `\0` вместо newline (за имена с интервали) |
| `-t`                | verbose — отпечатва командата преди изпълнение                        |
| `-p`                | интерактивен — пита за потвърждение преди всяко извикване             |
| `--no-run-if-empty` | не извиква командата ако stdin е празен                               |

#### `-I {}` — placeholder за позициониране

По подразбиране `xargs` добавя аргументите в **края** на командата. С `-I {}` можеш да контролираш точно **къде** се поставят:

```bash
# Без -I {} — аргументът отива в края
find . -name "*.conf" | xargs cp /backup/
# → cp /backup/ file1.conf file2.conf  ⚠️  грешен ред на аргументите

# С -I {} — {} се замества с аргумента
find . -name "*.conf" | xargs -I {} cp {} /backup/
# → cp file1.conf /backup/
# → cp file2.conf /backup/

# Примери с позициониране
find . -name "*.log" | xargs -I {} mv {} {}.bak        # преименува: app.log → app.log.bak
find . -name "*.txt" | xargs -I {} sh -c 'echo "=== {} ===" && cat {}'
ls *.jpg | xargs -I {} convert {} thumbnails/thumb_{}  # ImageMagick thumbnail
```

#### `-n` — брой аргументи на извикване

```bash
echo "a b c d e f" | xargs -n 2 echo
# echo a b
# echo c d
# echo e f

find . -name "*.txt" | xargs -n 1 wc -l    # wc за всеки файл поотделно
find . -name "*.txt" | xargs -n 3 cat      # cat на по 3 файла наведнъж
```

#### `-P` — паралелно изпълнение

```bash
# Компресира файловете паралелно с 4 процеса едновременно
find . -name "*.log" -mtime +30 | xargs -P 4 -I {} gzip {}

# Изтегля URL-и паралелно
cat urls.txt | xargs -P 8 -I {} curl -O {}
```

#### `-0` — безопасна работа с имена, съдържащи интервали

Стандартно `xargs` разделя аргументите по **интервали и нови редове** — файл с интервал в името се разбива на два аргумента и командата се проваля. Решението е `find -print0` и `xargs -0`, които ползват нулевия байт (`\0`) като разделител:

```bash
# Проблем — файл "my document.txt" се разбива
find . -name "*.txt" | xargs rm                  # ✗  "my" и "document.txt" се третират отделно

# Решение — нулев байт като разделител
find . -name "*.txt" -print0 | xargs -0 rm       # ✓  работи с всякакви имена
find . -name "*.txt" -print0 | xargs -0 -I {} cp {} /backup/
```

> **Добра практика:** Винаги използвай `-print0 | xargs -0` когато обработваш файлове — никога не знаеш дали имената съдържат интервали, скоби или Unicode символи.

#### `xargs` vs `find -exec`

И двата подхода вършат едно и също, но с различни компромиси:

|                        | `xargs`      | `find -exec ... \;`      | `find -exec ... +` |
| ---------------------- | ------------ | ------------------------ | ------------------ |
| Скорост                | ✅ бърз      | ❌ бавен (1 процес/файл) | ✅ бърз            |
| Паралелност            | ✅ с `-P`    | ❌                       | ❌                 |
| Имена с интервали      | с `-0`       | ✅ винаги                | ✅ винаги          |
| Работи с всяка команда | ✅           | ✅                       | ✅                 |
| Placeholder позиция    | ✅ с `-I {}` | ✅ с `{}`                | само в края        |

```bash
# Еквивалентни команди:
find . -name "*.tmp" -exec rm {} +          # find с -exec
find . -name "*.tmp" | xargs rm             # find с xargs

# xargs е по-удобен когато имаш готов списък (не само от find)
cat files_to_delete.txt | xargs rm
```

#### Практически примери

```bash
# Намери и изтрий всички node_modules директории
find . -type d -name "node_modules" -print0 | xargs -0 rm -rf

# Брои редовете на всички Python файлове в проект
find . -name "*.py" -print0 | xargs -0 wc -l | sort -n

# Замести "localhost" с "127.0.0.1" в всички конфигурационни файлове
find . -name "*.conf" -print0 | xargs -0 sed -i 's/localhost/127.0.0.1/g'

# Паралелно изтегляне на файлове от списък
cat download_list.txt | xargs -P 5 -I {} wget -q {}

# Намери дублирани файлове по MD5
find . -type f -print0 | xargs -0 md5sum | sort | uniq -d -w 32
```

## `grep` — търсене по шаблон

`grep` (**G**lobal **R**egular **E**xpression **P**rint), `sed` (**S**tream **ED**itor) и `awk` са трите основни инструмента за обработка на текст в Unix. Всеки от тях има различна роля: `grep` **намира** редове, `sed` **трансформира** ги, а `awk` работи с **структурирани данни** (полета/колони). Много често се комбинират заедно в pipeline.

`grep` търси редове, съвпадащи с даден шаблон — един от най-използваните инструменти в терминала.

### Как работи

`grep` чете входа **ред по ред**. За всеки ред проверява дали шаблонът съвпада някъде в него — ако да, отпечатва целия ред. Ако не — редът се пропуска.

```
Вход (ред по ред)          Шаблон: "error"        Изход
─────────────────────      ──────────────         ──────────────────────
"[INFO] server started"  → няма съвпадение   →   (пропуснат)
"[ERROR] connection lost" → съвпадение       →   "[ERROR] connection lost"
"[DEBUG] retrying..."    → няма съвпадение   →   (пропуснат)
"[ERROR] timeout"        → съвпадение        →   "[ERROR] timeout"
```

```bash
grep "error" log.txt              # редове съдържащи "error"
grep -i "error" log.txt           # без значение главни/малки букви
grep -v "debug" log.txt           # редовете, които НЕ съдържат "debug"
grep -n "error" log.txt           # показва номерата на редовете
grep -c "error" log.txt           # само броят на съвпадащите редове
grep -r "TODO" ./src/             # рекурсивно в директория
grep -l "error" *.log             # само имената на файловете (не съдържанието)
grep -w "log" file.txt            # само цялата дума "log" (не "logger")
```

> Важно: `grep` търси **съдържащ**, не **равен** — `grep "log"` ще намери и `"logger"`, и `"catalog"`, освен ако не ограничиш с `-w`.

| Флаг     | Значение                                    |
| -------- | ------------------------------------------- |
| `-i`     | case-insensitive                            |
| `-v`     | invert — редовете без съвпадение            |
| `-n`     | показва номера на реда                      |
| `-c`     | брои съвпаденията                           |
| `-r`     | рекурсивно в директории                     |
| `-l`     | само имената на файловете                   |
| `-w`     | само цели думи                              |
| `-A <N>` | показва N реда след съвпадението            |
| `-B <N>` | показва N реда преди съвпадението           |
| `-C <N>` | показва N реда преди И след (контекст)      |
| `-E`     | разширени регулярни изрази (като `egrep`)   |
| `-o`     | показва само съвпадащата част, не целия ред |

### Регулярни изрази (regex)

Шаблоните в `grep` могат да бъдат обикновен текст или **регулярни изрази** — специален синтаксис за описване на текстови шаблони. С флага `-E` се отключват разширените regex (ERE).

[Повече информация за регулярните изрази.](./Regex/README.md)

```bash
# Контекст около съвпадението
grep -C 3 "ERROR" app.log         # 3 реда преди и след всяка грешка

# Регулярни изрази
grep "^ERROR" log.txt             # редове, започващи с "ERROR"
grep "\.txt$" file.txt            # редове, завършващи с ".txt"
grep -E "error|warning" log.txt   # "error" ИЛИ "warning"
grep -E "[0-9]{3}" log.txt        # точно 3 цифри
grep -E "^[A-Z]" file.txt         # редове, започващи с главна буква

# В комбинация с pipe
cat access.log | grep "404" | wc -l          # брой 404 грешки
cat /etc/passwd | grep -v "^#" | cut -d: -f1 # потребителите без коментари
```

## `sed` — редактиране на потоци

`sed` (**S**tream **ED**itor) обработва текст ред по ред, прилагайки команди за трансформация. Не редактира файлове директно (по подразбиране) — чете вход, трансформира и отпечатва.

### Как работи

`sed` има **вътрешен цикъл** — той работи с два буфера: **pattern space** (работното пространство) и **hold space** (дългосрочна памет). За всеки ред от входа:

```
1. Чете реда и го поставя в pattern space
2. Изпълнява всички команди върху pattern space
3. Отпечатва pattern space (освен ако не е подаден -n)
4. Изчиства pattern space и преминава към следващия ред
```

```
Вход           pattern space        Команда: s/foo/bar/g       Изход
────────        ─────────────        ──────────────────────     ──────
"foo baz"   →   "foo baz"        →   замества → "bar baz"   →  "bar baz"
"hello"     →   "hello"          →   няма съвпадение         →  "hello"
"foo foo"   →   "foo foo"        →   замества → "bar bar"   →  "bar bar"
```

### Основен синтаксис

```bash
sed 'команда' файл
sed -e 'команда1' -e 'команда2' файл    # множество команди
sed -i 'команда' файл                   # редактира файла директно (in-place)
sed -i.bak 'команда' файл               # in-place, запазва backup с .bak
```

### Заместване `s///`

Най-използваната команда — `s/шаблон/замяна/флагове`.

Формата е:

```bash
sed 's/regex/замяна/флагове'
```

- `s` = substitute
- първият разделител след `s` тук е `/`, но може да бъде почти всеки символ: `s|old|new|`, `s#old#new#`
- `regex` е шаблонът, който `sed` търси
- `замяна` е текстът, който ще се постави вместо съвпадението
- `флагове` променят поведението (`g`, `i`, `2`, `p` и др.)

```bash
sed 's/foo/bar/' file.txt              # замества ПЪРВОТО "foo" на всеки ред
sed 's/foo/bar/g' file.txt             # замества ВСИЧКИ "foo" (g = global)
sed 's/foo/bar/i' file.txt             # без значение главни/малки букви
sed 's/foo/bar/2' file.txt             # замества само второто съвпадение
sed 's/foo/bar/gI' file.txt            # всички + case-insensitive

# Разделителят не е задължително /
sed 's|/old/path|/new/path|g' file.txt  # удобно при пътища
sed 's#foo#bar#g' file.txt              # работи с всеки символ
```

**Capture groups** — можеш да "захванеш" части от шаблона с `\(...\)` и да ги върнеш в замяната чрез `\1`, `\2`:

```bash
# Размени местата на две думи
echo "John Smith" | sed 's/\(.*\) \(.*\)/\2, \1/'   # Smith, John

# Обгради числата в скоби
echo "код 404 грешка" | sed 's/[0-9]\+/(&)/g'        # код (404) грешка
# & означава "цялото съвпадение"

# Добави http:// към URL-и без протокол
sed 's/^\(www\.\)/http:\/\/\1/' file.txt
```

### Какво означават `/.../.../`

При `s///` наклонените черти **не са част от regex-а** — те са просто **разделители** между трите части:

```bash
s / pattern / replacement / flags
```

Например:

```bash
sed 's/cat/dog/g'
```

се чете така:

- търси `cat`
- замени с `dog`
- `g` = направи го за всички съвпадения на реда

Когато самият шаблон съдържа `/`, се налага escape или смяна на разделителя:

```bash
sed 's/\/usr\/bin/\/opt\/bin/' file.txt
sed 's|/usr/bin|/opt/bin|' file.txt     # по-четимо
```

### Специални символи в replacement частта

В частта за замяна има няколко важни специални символа:

| Символ        | Значение                           |
| ------------- | ---------------------------------- |
| `&`           | цялото намерено съвпадение         |
| `\1`, `\2`... | съдържанието на capture групите    |
| `\\`          | буквален backslash                 |
| `\/`          | буквално `/`, ако `/` е разделител |

```bash
echo "error 404" | sed 's/[0-9][0-9]*/(&)/'
# error (404)

echo "abc123" | sed 's/[0-9][0-9]*/NUM-&/'
# abcNUM-123
```

### `-E` — разширени регулярни изрази

По подразбиране `sed` използва **BRE** (_Basic Regular Expressions_). Там някои конструкции трябва да се escape-ват. С `-E` се включват **ERE** (_Extended Regular Expressions_), които са по-удобни и по-четими.

Без `-E`:

```bash
echo "John Smith" | sed 's/\(.*\) \(.*\)/\2, \1/'
```

С `-E`:

```bash
echo "John Smith" | sed -E 's/(.*) (.*)/\2, \1/'
```

Основната разлика е, че при `-E` символите `()`, `+`, `?`, `{}` се ползват **директно**, без `\`.

| Искаш да използваш | Без `-E`     | С `-E`     |
| ------------------ | ------------ | ---------- |
| групиране          | `\(abc\)`    | `(abc)`    |
| едно или повече    | `a\+`        | `a+`       |
| 0 или 1            | `colou\?r`   | `colou?r`  |
| повторения         | `[0-9]\{3\}` | `[0-9]{3}` |

```bash
echo "abc123" | sed -E 's/[0-9]+/NUM/'
echo "color colour" | sed -E 's/colou?r/X/g'
echo "ID: 123-456" | sed -E 's/([0-9]{3})-([0-9]{3})/[\1][\2]/'
```

> **Практика:** Когато regex-ът не е съвсем тривиален, `sed -E` почти винаги е по-четим вариант.

### Изтриване на редове `d`

```bash
sed '3d' file.txt                      # изтрива 3-ти ред
sed '3,7d' file.txt                    # изтрива редове 3 до 7
sed '/pattern/d' file.txt              # изтрива редовете съдържащи pattern
sed '/^#/d' file.txt                   # изтрива коментари (редове с #)
sed '/^$/d' file.txt                   # изтрива празни редове
sed '/^[[:space:]]*$/d' file.txt       # изтрива редове само с интервали
```

### Принтиране `p`

```bash
sed -n '5p' file.txt                   # показва само 5-ти ред (-n спира стандартния изход)
sed -n '5,10p' file.txt                # показва редове 5 до 10
sed -n '/error/p' file.txt             # показва само редовете с "error"
```

### Адресиране

Адресирането казва на `sed` кои редове да обработва. Без адрес — командата се прилага към всички редове.

```bash
sed '2s/foo/bar/' file.txt             # замества само на ред 2
sed '2,5s/foo/bar/' file.txt           # само на редове 2-5
sed '/start/,/end/s/foo/bar/' file.txt # между редовете съдържащи start и end
sed '$s/foo/bar/' file.txt             # само на последния ред
sed '~2s/foo/bar/' file.txt            # на всеки втори ред (0, 2, 4…)
```

### In-place редактиране

```bash
sed -i 's/localhost/127.0.0.1/g' config.txt           # директна промяна
sed -i.bak 's/localhost/127.0.0.1/g' config.txt       # с backup
sed -i '/^#/d' config.txt                              # изтрива коментарите
```

```bash
# Практически примери
sed 's/^/  /' file.txt                 # добавя 2 интервала в началото на всеки ред
sed 's/ *$//' file.txt                 # премахва trailing whitespace
sed -n '10,20p' large_file.txt         # показва само редове 10-20 (по-бързо от head/tail)
sed 's/[0-9]\+/NUM/g' file.txt         # замества всички числа с "NUM"
```

### Множество команди в едно извикване

Командите в `sed` могат да се разделят с `;` или да се подадат с няколко флага `-e`. И двата варианта са еквивалентни — `-e` е по-четимо при по-дълги скриптове.

```bash
sed 's/foo/bar/; s/baz/qux/' file.txt
sed -e 's/foo/bar/' -e 's/baz/qux/' file.txt

# Скрипт от отделен файл с командите (една команда на ред)
sed -f script.sed file.txt
```

### Вмъкване, добавяне и промяна на редове — `i`, `a`, `c`

Тези три команди работят с **цели редове**, не с текст вътре в реда — удобни за добавяне на съдържание около съвпадение.

| Команда | Значение |
|---------|----------|
| `i\текст` | insert — вмъква нов ред **преди** адресирания ред |
| `a\текст` | append — вмъква нов ред **след** адресирания ред |
| `c\текст` | change — заменя целия адресиран ред с нов текст |

```bash
sed '3i\Нов ред преди 3-ти' file.txt
sed '3a\Нов ред след 3-ти' file.txt
sed '3c\Заменен трети ред' file.txt

sed '/^#/a\# --- край на коментарния блок ---' config.txt   # добавя ред след всеки коментар
sed '/ERROR/i\--- Внимание ---' log.txt                      # предупреждение преди всеки ред с ERROR
```

> В GNU sed синтаксисът работи и без `\` (`sed '3a Нов ред'`), но версията с `\` е по-преносима между различни имплементации (BSD/macOS `sed`).

### Транслитерация — `y///`

`y` замества **символ по символ** (не regex) — подобно на `tr`, но вътре в `sed`. Двата низа трябва да са с еднаква дължина.

```bash
echo "hello" | sed 'y/el/ip/'          # hippo
sed 'y/abc/xyz/' file.txt              # заменя всяко a→x, b→y, c→z
```

### Номер на текущия ред — `=`

```bash
sed '=' file.txt                       # отпечатва номера на реда преди самия ред
sed -n '/error/=' log.txt              # само номерата на редовете с "error"
```

### Ранно спиране — `q` и `Q`

```bash
sed '5q' file.txt                      # обработва до ред 5 и спира (отпечатва редове 1-5)
sed '/ERROR/q' log.txt                 # спира на първото съвпадение с ERROR
sed '5Q' file.txt                      # спира на ред 5, БЕЗ да го отпечата (GNU sed)
```

### Многоредова обработка — `n`, `N`, `P`, `D`

По подразбиране `sed` работи с **един ред наведнъж** в pattern space. Тези команди позволяват работа с **няколко реда едновременно** — полезно за замествания, които обхващат границата между два реда.

| Команда | Значение |
|---------|----------|
| `n` | отпечатва pattern space и зарежда **следващия** ред (замества текущия) |
| `N` | **добавя** следващия ред към pattern space (с `\n` между тях), вместо да го заменя |
| `P` | отпечатва само първия ред от pattern space (до първия `\n`) |
| `D` | изтрива първия ред от pattern space и рестартира цикъла без да чете нов вход |

```bash
# Слива всеки два реда в един, разделени с интервал
sed 'N;s/\n/ /' file.txt

# Премахва празен ред, ако следва веднага след друг празен ред
sed '/^$/{N;/^\n$/D}' file.txt

# Замяна, обхващаща два реда (напр. "край на изречение\nследва малка буква")
sed 'N;s/\.\n\([a-z]\)/. \1/;P;D' file.txt
```

### Hold space — `h`, `H`, `g`, `G`, `x`

`sed` разполага с втори буфер — **hold space** — за временно съхранение на текст между редовете. Полезен за задачи, изискващи "памет" през целия файл (обръщане на ред на редовете, дублиране, преместване на редове).

| Команда | Значение |
|---------|----------|
| `h` | копира pattern space **в** hold space (презаписва) |
| `H` | добавя pattern space **към** hold space (append, с `\n`) |
| `g` | копира hold space **в** pattern space (презаписва) |
| `G` | добавя hold space **към** pattern space (append) |
| `x` | разменя съдържанието на pattern space и hold space |

```bash
# Емулация на `tac` (обръща реда на редовете във файла)
sed '1!G;h;$!d' file.txt

# Удвоява всеки ред (добавя празен ред след всеки)
sed 'G' file.txt

# Отпечатва последния ред първи, чрез hold space
sed -n '1!G;h;$p' file.txt
```

> Hold space командите са мощни, но не са тривиални — за по-сложна логика с "памет" през целия файл, `awk` често е по-четим избор.

### Работа с NUL-разделени записи — `-z`

Подобно на `find -print0` / `xargs -0`, флагът `-z` кара `sed` да третира входа като записи, разделени с нулев байт вместо `\n` — полезно за имена на файлове с интервали или нови редове, или за третиране на целия файл като един "ред" (paragraph mode).

```bash
find . -print0 | sed -z 's/foo/bar/'   # работи безопасно с "странни" имена на файлове
```

### Обработка на всеки файл поотделно — `-s`

Когато подадеш няколко файла, по подразбиране `sed` третира целия вход като един непрекъснат поток (напр. номерата на редовете с `=` продължават през файловете). `-s` кара `sed` да рестартира състоянието (включително номерацията на редовете и `$` за последен ред) за всеки файл поотделно.

```bash
sed -s '$p' file1.txt file2.txt        # последният ред на ВСЕКИ файл, не само на общия вход
```

### Промяна на главни/малки букви в замяната (GNU sed)

GNU `sed` поддържа специални escape последователности в частта за замяна, които променят регистъра на следващия текст:

| Escape | Значение |
|--------|----------|
| `\U` | всичко след това — главни букви, до `\E` |
| `\L` | всичко след това — малки букви, до `\E` |
| `\u` | само следващата буква — главна |
| `\l` | само следващата буква — малка |
| `\E` | спира ефекта на `\U`/`\L` |

```bash
echo "hello world" | sed 's/.*/\U&/'          # HELLO WORLD
echo "HELLO WORLD" | sed 's/.*/\L&/'          # hello world
echo "hello" | sed 's/\(.*\)/\u\1/'           # Hello (главна само първата буква)
```

### Полезни едноредови "рецепти" (sed one-liners)

```bash
sed -n '$p' file.txt                    # само последният ред
sed -n '1p;$p' file.txt                 # първи и последен ред
sed '/^$/d' file.txt                    # премахва всички празни редове
sed '/^$/N;/\n$/D'                      # свива множество последователни празни редове в един
sed -n '/START/,/END/p' file.txt        # отпечатва блок между два маркера (вкл. границите)
sed '1!G;h;$!d' file.txt                # обръща реда на редовете (tac)
sed = file.txt | sed 'N;s/\n/\t/'       # номерира редовете, разделени с tab
```

> **`sed` срещу `awk`:** `sed` е специализиран за замествания и линейни трансформации на текст с прост regex синтаксис. Когато трябва аритметика, масиви, множество колони или по-сложна логика, `awk` обикновено е по-подходящ и по-четим избор.

## `awk` — обработка на структурирани данни

`awk` е малък програмен език, специализиран в обработката на текст, организиран в **полета и редове**. Изключително мощен за работа с табулирани данни — може да филтрира, трансформира, сумира и форматира без да пишеш отделна програма.

### Как работи

`awk` чете входа **ред по ред**. Всеки ред автоматично се разделя на **полета** по разделител (по подразбиране: всяка последователност от интервали/табове). Полетата са достъпни като `$1`, `$2`, `$3`…

Програмата в `awk` е изградена от блокове с формат `шаблон { действие }`. За всеки ред `awk` проверява шаблона — ако съвпада, изпълнява действието. Ако шаблонът е пропуснат — действието се изпълнява за всеки ред.

```
Програма:  шаблон { действие }
           ───────  ──────────
           кога?    какво?

Примери:
  { print $1 }           → за ВСЕКИ ред, отпечатай първото поле
  NR > 1 { print $0 }    → само ако номерът на реда е > 1
  /error/ { print $0 }   → само ако редът съдържа "error"
  $3 > 100 { print $1 }  → само ако третото поле е > 100
```

```
Вход:  "ivan   25  developer"
        │       │   │
        $1      $2  $3          $0 = целият ред
        NF = 3  (три полета)    NR = 1 (първи ред)
```

```bash
echo "ivan 25 developer" | awk '{print $1}'     # ivan
echo "ivan 25 developer" | awk '{print $3}'     # developer
echo "ivan 25 developer" | awk '{print $2, $1}' # 25 ivan
```

### `pattern { action }` — сърцето на `awk`

Най-важната идея в `awk` е формата:

```awk
pattern { action }
```

- `pattern` казва **кога** да се изпълни блокът
- `{ action }` казва **какво** да се направи
- за всеки входен ред `awk` проверява pattern-а
- ако pattern-ът е истина, изпълнява действието
- ако няма `pattern`, действието важи за **всички** редове
- ако няма `{ action }`, по подразбиране се прави `print $0`

Това води до няколко много важни случая:

```bash
awk '{print $1}' file.txt         # няма pattern → за всеки ред
awk '/error/ {print $0}' file.txt # pattern е regex
awk 'NR > 1 {print $1}' file.txt  # pattern е условие
awk '/error/' file.txt            # без action → print $0
```

### Какво може да бъде `pattern`

`pattern` в `awk` не е само regex. Може да бъде:

1. **Регулярен израз**
2. **Сравнение / логически израз**
3. **Комбинация от условия**
4. **Диапазон от два pattern-а**
5. **Специалните `BEGIN` и `END`**

##### 1) Regex pattern

```bash
awk '/error/ {print $0}' log.txt
awk '/^ERROR/ {print $0}' log.txt
awk '/[0-9]{3}/ {print $1}' file.txt
```

Тук pattern-ът е истина, ако regex-ът съвпадне с текущия ред (`$0`).

##### 2) Условен pattern

```bash
awk '$3 > 100 {print $1, $3}' file.txt
awk '$1 == "ivan" {print $0}' file.txt
awk 'NF == 3 {print $0}' file.txt
```

##### 3) Комбиниран pattern

```bash
awk 'NR > 1 && $2 >= 60 {print $1, $2}' scores.txt
awk '$1 == "ivan" || $1 == "maria" {print $0}' file.txt
awk '!/debug/ {print $0}' log.txt
```

##### 4) Диапазонен pattern

Два pattern-а, разделени със запетая, означават: **от първото съвпадение на левия pattern до първото следващо съвпадение на десния pattern**, включително.

```bash
awk '/START/,/END/' file.txt
awk 'NR==10,NR==20' file.txt
```

##### 5) `BEGIN` и `END`

Те не работят върху редове, а върху началото и края на изпълнението:

```bash
awk 'BEGIN {FS=":"} $3 >= 1000 {print $1} END {print "done"}' /etc/passwd
```

### Какво има вътре в `{}`

Скобите `{}` съдържат **действията** — това на практика е кодът, който `awk` изпълнява. Там можеш да имаш:

- `print`, `printf`
- присвояване на променливи
- `if`, `for`, `while`
- аритметика
- масиви
- извикване на функции

```bash
awk '{sum += $2; print $1, $2}' file.txt
awk '{if ($3 > max) max = $3} END {print max}' file.txt
awk '{count[$1]++} END {for (k in count) print k, count[k]}' file.txt
```

Може да има и **повече от едно действие** в един блок:

```bash
awk '$3 > 100 { sum += $3; count++; print $1, $3 } END { print "avg =", sum/count }' file.txt
```

### Кога може да се пропуснат `{}`

Скобите не могат просто да се пропускат, когато искаш да изпълниш действие. Но ако искаш само филтриране и стандартно отпечатване на реда, можеш да оставиш само pattern:

```bash
awk '$3 > 100' file.txt     # еквивалентно на: awk '$3 > 100 {print $0}'
awk '/error/' log.txt       # еквивалентно на: awk '/error/ {print $0}'
```

### Няколко pattern/action блока в една програма

Една awk програма може да има **няколко блока**, които се изпълняват един след друг върху всеки ред:

```bash
awk '
BEGIN { FS=":"; OFS="," }
$3 >= 1000 { print $1, $3 }
END { print "Край на обработката" }
' /etc/passwd
```

Мисли за това като за поредица от правила:

```
за всеки ред:
  правило 1 → ако съвпада, изпълни
  правило 2 → ако съвпада, изпълни
  правило 3 → ако съвпада, изпълни
```

### `[]` в `awk` — два различни смисъла

В `awk` квадратните скоби `[]` се срещат в **два напълно различни контекста**:

##### 1) В regex — клас символи

```bash
awk '/[0-9]/' file.txt        # редове, съдържащи цифра
awk '/^[A-Z]/' file.txt       # редове, започващи с главна буква
awk '/[abc]/' file.txt        # редове с a, b или c
```

Тук `[]` значи „един символ от този набор“.

##### 2) При асоциативни масиви — индексиране

```bash
awk '{count[$1]++} END {for (k in count) print k, count[k]}' file.txt
```

Тук `count[$1]` **не е regex**, а достъп до елемент в масив. `awk` има асоциативни масиви — индексът може да е текст, не само число.

```bash
awk '
{ users[$1] += $2 }
END {
  for (u in users)
    print u, users[u]
}' sales.txt
```

- `users["ivan"]` може да пази сума за `ivan`
- `seen[$0]++` е често срещан шаблон за броене на редове
- `arr[key]` е като dictionary/map в други езици

### Специални променливи

| Променлива | Значение                                                                |
| ---------- | ----------------------------------------------------------------------- |
| `$0`       | целият текущ ред                                                        |
| `$1, $2…`  | полета по ред                                                           |
| `NF`       | **N**umber of **F**ields — броят на полетата в текущия ред              |
| `NR`       | **N**umber of **R**ecords — номерът на текущия ред (от началото)        |
| `FNR`      | номерът на реда в текущия файл (при множество файлове)                  |
| `FS`       | **F**ield **S**eparator — разделителят на полетата (по подр.: интервал) |
| `OFS`      | **O**utput **F**ield **S**eparator — разделителят в изхода              |
| `RS`       | **R**ecord **S**eparator — разделителят на редовете (по подр.: \n)      |
| `ORS`      | **O**utput **R**ecord **S**eparator                                     |

```bash
echo "ivan 25 developer" | awk '{print NF}'     # 3 — три полета
echo "ivan 25 developer" | awk '{print $NF}'    # developer — последното поле
echo "ivan 25 developer" | awk '{print $(NF-1)}'  # 25 — предпоследното поле
```

### BEGIN и END

`BEGIN` и `END` са специални шаблони — не съвпадат с редове от входа, а с **моменти от изпълнението**. `BEGIN` се изпълнява веднъж преди четенето на първия ред — използва се за инициализация на променливи и задаване на разделители. `END` се изпълнява веднъж след последния ред — идеален за обобщения и финални изчисления.

```
BEGIN  →  { инициализация }
           ↓
ред 1  →  { обработка }
ред 2  →  { обработка }
  ...
ред N  →  { обработка }
           ↓
END    →  { обобщение, финален изход }
```

```bash
awk 'BEGIN { print "Начало" } { print $0 } END { print "Край" }' file.txt

# Брои редовете (като wc -l)
awk 'END { print NR }' file.txt

# Сумира числата в първата колона
awk '{ sum += $1 } END { print "Сума:", sum }' numbers.txt

# Среден брой думи на ред
awk '{ total += NF } END { print "Средно:", total/NR, "думи/ред" }' file.txt
```

### Разделител на полетата

```bash
awk -F: '{print $1}' /etc/passwd               # : като разделител
awk -F, '{print $2}' data.csv                  # , за CSV
awk -F'\t' '{print $3}' data.tsv               # tab разделител
awk 'BEGIN{FS=":"} {print $1}' /etc/passwd     # FS в BEGIN блока
```

### Условия и филтриране

```bash
awk '$3 > 100' file.txt                        # редове, където $3 > 100
awk '$1 == "ivan"' file.txt                    # само редове с ivan в $1
awk 'NR > 1' file.txt                          # пропуска първия ред (header)
awk 'NR % 2 == 0' file.txt                     # само четните редове
awk '/error/' file.txt                         # редове съдържащи "error" (като grep)
awk '!/debug/' file.txt                        # редове без "debug"
awk 'NR >= 5 && NR <= 10' file.txt             # редове 5 до 10
```

### Форматиран изход с printf

```bash
awk '{printf "%-20s %5d\n", $1, $2}' file.txt
#    └── %-20s: стринг, 20 символа, ляво наредено
#               └── %5d: число, 5 символа, дясно наредено

awk '{printf "%s\t%s\n", $1, $3}' file.txt    # tab разделени колони
```

### Практически примери

```bash
# Покажи само потребителите от /etc/passwd с UID >= 1000
awk -F: '$3 >= 1000 {print $1, $3}' /etc/passwd

# Намери най-голямата стойност в колона
awk 'BEGIN{max=0} $1>max{max=$1} END{print "Макс:", max}' numbers.txt

# Брои уникалните стойности в първата колона
awk '{count[$1]++} END {for (k in count) print k, count[k]}' file.txt

# Сумира размерите от ls -l
ls -l | awk 'NR>1 {sum += $5} END {print "Общо:", sum, "байта"}'

# Промени разделителя от : на ,
awk -F: 'BEGIN{OFS=","} {print $1,$3,$6}' /etc/passwd

# Покажи дублираните редове
awk 'seen[$0]++' file.txt

# Покажи редове между два шаблона
awk '/START/,/END/' file.txt
```

### Сравнение на инструментите

| Инструмент | Добър за                                                |
| ---------- | ------------------------------------------------------- |
| `grep`     | намиране и филтриране на редове по шаблон               |
| `sed`      | заместване, изтриване и трансформация на текст          |
| `cut`      | бързо извличане на колони по фиксиран разделител        |
| `awk`      | обработка на структурирани данни, аритметика, обобщения |

Трите инструмента покриват различни нужди и в реална работа почти винаги се използват заедно в pipeline. Данните текат от ляво на дясно — изходът на всяка команда става входът на следващата:

```bash
cat access.log | grep "POST" | awk '{print $7}' | sort | uniq -c | sort -rn | head -10

# Стъпки:
# 1. grep    — филтрира само POST заявките
# 2. awk     — извлича само URL-а (7-мо поле)
# 3. sort    — сортира URL-ите азбучно (нужно преди uniq)
# 4. uniq -c — брои колко пъти се появява всеки URL
# 5. sort -rn — сортира числово в обратен ред (най-много отгоре)
# 6. head -10 — взима само топ 10
# Резултат: Топ 10 POST endpoints по брой заявки
```
